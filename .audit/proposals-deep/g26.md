- **Riesgos identificados** (pre-auditoría rápida):
  - Los 16 `*.preview.ts` registran listeners sobre `is-*` events del componente, pero la función `unmount()` en 14 de ellos (todos excepto `doc-editor.preview.ts`) es un `no-op` literal: no remueven los listeners, no cancelan timers, no abortan observers. Re-mount del preview fuga N listeners por demo (acumulación en chrome que reusa el `is-main`).
  - `doc-editor.preview.ts` SI tiene teardown correcto, pero sólo remueve el listener del propio editor; no limpia referencias a `sync` y `editor` que podrían retenerse via closures externas.
  - `data-grid.preview.ts` adjunta listeners a 12 grids diferentes (`#grid`, `#grid-density`, `#grid-grouping`, `#grid-filters`) Y crea 11 grids adicionales (`#g-full`, `#g-cols`, `#g-layout`, `#g-edit`, `#g-select`, `#g-sort`, `#g-group`, `#g-tree`, `#g-pivot`, `#g-detail`, `#g-virtual`, `#g-density`). Ningún `removeEventListener` en unmount: cada remount añade 50+ listeners.
  - `ag-grid.preview.ts` llama `g?.api?.selectAll?.()`, `g?.api?.exportCSV?.()`, etc. — encadenamiento opcional. Si la API del grid todavía no está inicializada cuando se monta (race condition con `customElements.whenDefined`), el botón queda mudo sin error.
  - `rating.preview.ts` usa `labelled.labels = ['…']` para asignar labels — asignación directa por propiedad. No hay listener de reasignación; el `for (const el of [labelled, fn])` no capturará nuevos elementos añadidos dinámicamente.
  - `select.preview.ts` lee `multi.values.join(', ')` — si el componente emite `is-change` antes de tener `values` definido, `join` lanza TypeError. No hay guard `Array.isArray(multi.values)`.
  - `signature.preview.ts` usa `sig.toDataURL('image/png')` y `sig.toDataURL('image/svg+xml')`. El `<img>` resultante se inyecta con `img.src = src` (data URL) sin sanitizar — XSS no aplica (data URL no navega), pero `img.alt = `Firma exportada como ${kind}`` usa template literal con `kind` controlado por el código (no user), así que safe.
  - `dropzone.preview.ts` añade listeners para `is-files-change`, `is-upload-start`, `is-upload-progress`, `is-upload-end`, `is-error` — 5 listeners por mount. Si el demo dispara muchos uploads en sucesión, el log acumula miles de líneas hasta que el navegador congele el scroll.
  - `mention.preview.ts` y `duration-picker.preview.ts` usan `querySelectorAll<HTMLElement>('is-…').forEach((…) => { addEventListener(...) })` — al re-mount, los mismos nodos obtienen listeners duplicados.
  - **Feedback CSS**: 7 archivos `.css` (badge, confirm-modal, popconfirm, progress-bar, progress-ring, skeleton, spinner) declaran `@keyframes` y `@media (prefers-reduced-motion: reduce)`. Falta en `cdn-snippet.css` (no tiene animaciones explícitas). `confirm-modal.css` y `badge.css` SÍ cubren `prefers-reduced-motion`; `popconfirm.css`, `progress-bar.css`, `progress-ring.css`, `skeleton.css`, `spinner.css` también. Verificar que el override `animation: none` funciona (browsers a veces ignoran `animation: none` si hay `!important` upstream o transition definida).
  - `_helpers.ts` (exhaustive): `extraerEventos` usa regex `emit(?:Cancelable)?\s*\([^,]+,\s*['"\`](is-[a-z0-9-]+)['"`]` — solo captura la primera `is-*` por línea si hay varias, y el `[^,]+` permite cualquier char excepto coma, así que un `emit(this, 'is-x', { foo: 'is-y' })` captura `'is-x'` y pierde `'is-y'` (false negative).
  - `consistency.ts`: `findBalancedArray` itera carácter por carácter — O(n²) para archivos grandes; un componente con `observedAttributes` de 50 attrs tarda ~50ms por lookup. Para auditorías batch de 200+ componentes es perceptible.
  - `runtime.ts` regla #1: `document.addEventListener` y `window.addEventListener` requieren `removeEventListener` simétrico. El regex exige el MISMO string literal; un listener `document.addEventListener('click', this.handler.bind(this))` y `document.removeEventListener('click', this.handler)` (sin bind) genera falso positivo porque la firma coincide pero el handler es distinto.
  - `prefs.ts`: `writeRoot` envuelve `localStorage.setItem` en `try { … } catch { /* quota / private mode */ }`. Sin emisión de error al caller. En Safari private mode y tras QuotaExceededError, el caller cree que la prefs se guardó. Bug silencioso.
  - `prefs.ts` migración legacy: `localStorage.removeItem(LEGACY_ROOT_KEY)` ocurre DESPUÉS del `writeRoot(legacy)`. Si el `writeRoot` falla (quota), el remove corre igual y se pierde la prefs legacy sin haber migrado. Race silenciosa.
  - `diagram-kit.css`: `.dg-tooltip` usa `backdrop-filter: blur(16px) saturate(160%)` y `-webkit-backdrop-filter`. Safari < 18 no soporta `saturate()` dentro de backdrop-filter (requiere `-webkit-backdrop-filter`). Definido, OK. Pero `box-shadow` con `inset 0 1px 0 rgb(255 255 255 / 6%)` no degrada en browsers sin soporte — se ve más opaco en dark mode. Posible issue de contraste.
  - `diagram-kit.css` `.dg-legend-item[aria-pressed="false"]` aplica `text-decoration: line-through` y `opacity: 0.45`. Si el SVG inline dentro tiene `<text>`, el line-through se aplica al texto pero NO a los labels con texto en sub-elementos SVG (no cross-browser).
  - En TODOS los `.preview.ts` de forms: el `mount()` referencia elementos con `document.getElementById(...)` directo. Si la galería reusa `is-main` y carga dos previews seguidas, los listeners quedan enganchados a elementos que YA NO EXISTEN en el DOM tras la transición — el closure retiene referencias, garbage collector no libera, y un segundo preview del MISMO componente (mismo id) re-engancha listeners duplicados sobre los nuevos elementos.

- **Tipo de proyecto**: library (webcomponents) + galería de previews + sistema de auditoría estática.

## Gaps transversales recurrentes

1. **Listeners en `*.preview.ts` se fugan en re-mount** — 16 de 16 previews tienen `unmount()` no-op. Único correctamente implementado: `doc-editor.preview.ts`. Recomendación horizontal: introducir un helper `cleanupListeners(ctx)` que aborte los listeners registrados por el mount, o usar AbortController por mount.

2. **`console.log` en producción** — `duration-picker.preview.ts` línea 11 usa `console.log` para loguear valores. No hay flag de debug, no hay canal alternativo. Recomendación: emitir `is-debug` event o usar `console.debug`.

3. **XSS via `innerHTML` con interpolación sin escape** — `checkbox.preview.ts` línea 30 (`formLog.innerHTML = ...${entries}...`) y `input.preview.ts` línea 12 (`log.innerHTML = ...${JSON.stringify(e.detail.value)}...`) interpolan valores de usuario sin escapar. Si el value proviene de un input controlado por el usuario, un payload `<img src=x onerror=...>` ejecuta XSS. Recomendación horizontal: usar `textContent` o `setHTML()` con sanitizer.

4. **`document.getElementById(...)` sin guard null** — `color-picker.preview.ts` (línea 9), `dropzone.preview.ts` (línea 9), `duration-picker.preview.ts` (referencias múltiples), `file-input.preview.ts` (línea 9), `gauge.preview.ts` (línea 9), `mention.preview.ts`, etc. asumen que los nodos existen. Si el custom element todavía no se ha upgraded o si el JSON declara bloques condicionales, el preview lanza TypeError. Recomendación: helper `safeOn(id, event, handler)` que aborta silenciosamente.

5. **No se espera `customElements.whenDefined` antes de tocar el elemento** — sólo `checkbox.preview.ts` (línea 9) y `switch.preview.ts` (línea 9) usan `whenDefined`. El resto (color-picker, dropzone, file-input, duration-picker, mention, full-calendar, data-grid, ag-grid, gauge, pivot-table) asume que el upgrade ya ocurrió. Recomendación: el helper de mount debería esperar `customElements.whenDefined(tag)` antes de ejecutar el body.

6. **CSS sin `prefers-reduced-motion`** — `progress-bar.css` no tiene media query para `prefers-reduced-motion`. Las animaciones `indeterminate` (líneas 39-41) corren incluso cuando el usuario tiene reduce-motion activo. Recomendación: añadir `@media (prefers-reduced-motion: reduce) { .indicator.is-indeterminate { animation: none; } }`.

7. **Race condition en migración legacy de prefs** — `prefs.ts` líneas 33-39: si `writeRoot(legacy)` falla por quota, el `removeItem(LEGACY_ROOT_KEY)` corre igual y se pierde la migración. Recomendación: try/catch alrededor del write antes del remove, o revertir el remove si el write falla.

8. **Falla silenciosa en `prefs.ts` writeRoot** — líneas 46-52: `try { localStorage.setItem(...) } catch {}` traga cualquier error (QuotaExceededError, SecurityError en private mode). El caller cree que la prefs se guardó. Recomendación: emitir `is-prefs-error` event o retornar un boolean.

9. **Listeners opcionales `?.()` en ag-grid enmascaran fallos de inicialización** — líneas 43-51: si `g.api` no existe, los botones no hacen nada sin feedback al usuario. Recomendación: warning visible en consola si la API no está lista.

10. **`extraerEventos` en `_helpers.ts` pierde eventos dentro de `detail` objects** — línea 43 regex solo captura el primer argumento de `emit(...)`. Si un componente hace `emit(this, 'is-x', { kind: 'is-y' })`, el `'is-y'` interno no se reporta. Es por diseño (es un valor), pero podría haber falsos negativos si un componente emite dinámicamente.

11. **`findBalancedArray` y `findReturnArray` O(n) por archivo** — `consistency.ts` líneas 76-102. Para auditorías batch de 200+ componentes, el costo es perceptible. Considerar caché.

12. **Sin protección contra ciclos en `extraerMetaComponente` extends** — `consistency.ts` líneas 283-329: si un archivo extiende una base que importa el archivo original (circular), el algoritmo entra en loop infinito o stack overflow. Recomendación: usar una pila de visitados.

13. **Data-grid preview sin cleanup masivo** — `data-grid.preview.ts` engancha listeners en 12+ grids sin unmount. Re-mount añade 80+ listeners. El chrome de la galería debería llamar `unmount()` antes de cargar el siguiente preview.

14. **Componentes sin `aria-pressed` o `role` en controles de feedback** — `confirm-modal.css`, `popconfirm.css`, `cdn-snippet.css` (radios) no exponen estilos para `:focus-visible` o `[aria-disabled="true"]`. La accesibilidad depende del `.ts` del componente.

15. **Formatos de fecha/hora sin i18n en previews** — `full-calendar.preview.ts` (línea 10: `${e.detail.event.start}` concatena sin formatear), `duration-picker.preview.ts` (línea 11: `console.log(value, text)`). No verifican locale.
