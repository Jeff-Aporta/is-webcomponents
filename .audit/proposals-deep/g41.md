# Auditoría F0.3 — webcomponent/components/forms+navigation+isp+utils+components+previews (g41)

## Contexto

- **Testables del grupo** (56 items): ver `LISTA` completa abajo en la sección *Discrepancias de nomenclatura*.
- **Lenguaje(s)**: TypeScript (vanilla Web Components + Shadow DOM). Zero runtime dependencies. Estilos en CSS por componente (`*.css` con `adoptCss`).
- **Tests existentes**: NINGUNO de los paths listados en el prompt (`src/components/forms/*.test.ts`, `src/components/navigation/*.test.ts`, `src/components/_shared/*.test.ts`, `src/components/feedback/*.test.ts`, `src/components/helpers/*.test.ts`, `src/components/isp/_shared/tree-view/*.test.ts`, `src/components/isp/*.test.ts`, `src/utils/health/motor/*.test.ts`, `src/components/_shared/llm-agent-prompt.test.ts`, `src/previews/_kit/load-json.test.ts`) **existe en disco** (verificado `Test-Path`: 0/54 = MISSING).
  - Sí existen **otros** `.test.ts` paralelos en `src/utils/health/exhaustive/{forms,navigation,actions,helpers,isp,…}/*.test.ts` (≈100+ archivos). Esos tests validan **contrato estático** del código fuente (atributos observados, eventos emitidos, slots declarados, parts, custom-states, form-associated, shadow DOM) usando `node:test` + un helper `_helpers.js`. **No** son tests de runtime/UI/UX ni de DOM interaction, así que **no cubren** keyboard, a11y, focus management, ARIA states, eventos, integración, performance, etc.
  - Categorías cubiertas por los `exhaustive/*.test.ts`: contrato estático (presencia de atributos, eventos, parts) — NO comportamiento.
- **Riesgos identificados** (pre-auditoría rápida):
  1. Web Components complejos (date-picker, full-calendar, slider, mega-menu, tree, carousel, time-clock) carecen de tests de teclado/a11y/focus-management → riesgo alto de regresiones de accesibilidad.
  2. Componentes `form-associated` (checkbox, switch, radio-group, select, combobox, input, masked-input, textarea, color-picker, duration-picker, file-input, slider, rating, mention, inline-edit, doc-editor, pin-input) — la validación `ElementInternals` no está cubierta (formData, reset, disabled form).
  3. `<dialog modal>` top-layer para select/combobox/color-picker — no hay test de focus-trap, Escape-close, backdrop-click.
  4. `ScrollMemory` (storage + restorePolicy) — lógica con TTL, debounce, AbortController: alta superficie de bugs no cubierta.
  5. Helpers puros (`grid-data.ts`) — funciones puras sin tests; riesgo de drift en `normalizeColumns`, `resolveWidths`, `filterTest`, etc.
  6. CLI del motor auditor (`cli.ts`, `reporter.ts`) — exit codes, parsing de args, formato JSON/Markdown no cubiertos.
- **Tipo de proyecto**: librería frontend (Web Components is-\*, vanilla TS, Shadow DOM).

## Regla de cobertura aplicada

- ≥8 propuestas por testable para archivos cortos (<200 LOC).
- ≥10 propuestas para archivos medianos (200–500 LOC).
- ≥12 para archivos grandes (>500 LOC) o con superficie de eventos/API amplia.
- Categorías adaptadas al tipo: UI/UX, keyboard, ARIA/a11y, focus management, integración, eventos custom, edge cases numéricos/fechas, browser APIs, performance, reduced-motion, security (XSS en `escapeHtml`).

## Propuestas por testable

> Las propuestas usan **selectores relativos al Shadow DOM del componente** (e.g. `>>>` pierce-shadow con Playwright `>>` syntax). Para componentes que exponen `<dialog>`, los selectores deben cruzar el shadow boundary con `chromium` (puede requerir `[open]` o top-layer pseudo-selectors como `dialog[open]`).

## Gaps transversales recurrentes

1. **Tests de contrato estático ≠ tests de comportamiento**: los `exhaustive/*.test.ts` validan la presencia de atributos/eventos/parts pero no prueban que se emitan correctamente, ni keyboard, ni ARIA, ni focus. **Oportunidad**: crear tests de comportamiento paralelos (Playwright + jsdom) para todos los componentes form-associated e interactivos.

2. **Focus-trap y `Escape`-close en `<dialog>` top-layer**: los popups de `select`, `combobox` y `color-picker` usan `<dialog modal>`. No hay tests que verifiquen:
   - Que el foco se mantiene dentro del dialog mientras está abierto.
   - Que `Escape` cierra consistentemente en los 3.
   - Que el click en backdrop cierra.
   - **Oportunidad**: helper compartido `dialogA11ySpec.ts` con los 3 escenarios.

3. **`reduced-motion` coverage inconsistente**: muchos componentes exponen tokens CSS y animaciones, pero solo algunos lo testean. **Oportunidad**: spec horizontal `prefers-reduced-motion.test.ts` que recorra todos los componentes con animaciones declaradas.

4. **Web OTP / Browser APIs**: `pin-input`, `input` y `masked-input` usan Web OTP API. Solo se propone 1 test por componente. **Oportunidad**: helper compartido para mockear `OTPCredential` y reusar.

5. **Form-associated reset behavior**: `formResetCallback`, `formDisabledCallback`, `formStateRestoreCallback` están en `slider.ts` y otros form-associated. No hay tests sistemáticos. **Oportunidad**: spec helper `form-associated.test.ts` con tabla de componentes y callbacks.

6. **XSS via `value` / `innerHTML`**: `signature.ts` (escapeHtml en events), `doc-editor.ts` (value JSON parseado), `rte.ts` (HTML directo), `radio.ts` (label). Cada uno propone 1 test de XSS. **Oportunidad**: spec transversal `xss-prevention.test.ts` que recorra los componentes que renderizan HTML desde el usuario.

7. **`url-nav` / `url-key` (tab-group)**: persistencia del estado en URL no está testeada. Si otros componentes adoptan este patrón, debe tener coverage.

8. **`escapeHtml` helper usage**: el helper vive en `_shared/dom-utils.js`. No se testea unitariamente. **Oportunidad**: tests directos del helper.

9. **CSS parts / custom states coverage**: `src/utils/health/exhaustive/domain/css-imports.test.ts` y similares validan estático. Falta validar visualmente (computed style) que los parts exponen estilos correctos cuando se les aplica CSS externo.

10. **i18n: locale fallbacks**: varios componentes aceptan `locale` y caen al `documentElement.lang`. No hay tests de fallback chain. **Oportunidad**: spec transversal.

11. **`<dialog modal>` positioning**: select/combobox/color-picker usan `<dialog>` top-layer. Tests manuales de positioning con `overflow: hidden` ancestors faltan en algunos. **Oportunidad**: regression test global.

12. **`<is-rte>` `registerRteCommand` API expuesta pero no testeada**: extensión por terceros. Si no se prueba, un cambio puede romper integraciones externas silenciosamente.

13. **`<is-full-calendar>` events sin eventos `title` con HTML**: aunque `escapeHtml` está aplicado, no hay test de XSS con títulos largos o caracteres especiales (RTL, emojis, etc.).

14. **`<is-grid-data>` (funciones puras)**: la batería de tests debería ser exhaustiva porque es worker code consumido por múltiples componentes. Solo se proponen 12 tests; podrían ser 30+ (uno por función/branch).

15. **`<is-scroll-memory>` time-based logic**: el TTL, restorePolicy, debounce y USER_INTENT dependen de `setTimeout`/`setInterval`. No hay tests con FakeTimers. **Oportunidad**: `sinon.useFakeTimers()` o `vi.useFakeTimers()`.

## Notas para el runner de tests

### Stack recomendado

- **Unit (funciones puras, DOM-less)**: `node:test` + `node:assert/strict` (consistente con `exhaustive/*.test.ts` existente).
- **DOM (web components en jsdom o happy-dom)**: `@open-wc/testing` + helpers de Lit ecosystem, o Web Test Runner.
- **Browser E2E**: Playwright (ya en uso por el motor auditor).
- **Visual/regression**: Percy o Chromatic si se quiere validar CSS (opcional).

### Setup de tests Playwright para webcomponents

```typescript
import { test, expect } from '@playwright/test';

test.beforeEach(async ({ page }) => {
  // Cargar el bundle del componente específico
  await page.addScriptTag({ url: '/dist/cdn/forms/checkbox.min.js' });
  // O importar via import map para ESM
});
```

### Selectores para Shadow DOM (Playwright)

Playwright pierce-shadow automáticamente con `>>>`:
- `page.locator('is-checkbox >>> [part="control"]')` — encuentra dentro del shadow.
- `page.locator('is-checkbox').evaluate(el => el.shadowRoot.querySelector('[part="control"]'))` — alternativa programática.

### Mocking de browser APIs

```typescript
// Web OTP
await page.addInitScript(() => {
  (globalThis as any).OTPCredential = class OTPCredential {

  };
});

// EyeDropper
await page.addInitScript(() => {
  (window as any).EyeDropper = class { open() { return Promise.resolve({ sRGBHex: '#ff0000' }); } };

// reduced-motion
await page.emulateMedia({ reducedMotion: 'reduce' });
```
