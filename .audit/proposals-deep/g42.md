- **Riesgos identificados** (pre-auditoría rápida):
  - **Listeners globales sin teardown**: `observer.ts` reconecta en cada `slotchange` sin desconectar el anterior `MutationObserver`/`ResizeObserver`/`IntersectionObserver` — fuga silenciosa de observers por cada mutación de slot. `wake-lock.ts` registra `visibilitychange` en `document` y lo quita en `disconnectedCallback`, pero `#acquire` puede quedar pendiente si el host se desconecta a mitad de `await navigator.wakeLock.request`.
  - **Persistencia de timers en `relative-time.ts`/`format.ts`**: `setInterval(…, 30000)` se limpia en `onDisconnected` pero NO se cancela si el atributo `sync` se quita en caliente — el componente sigue re-renderizando cada 30s aunque `sync` ya no esté.
  - **`popover.ts` con un único "abierto" global (`openPopover`)**: abrir un segundo popover cierra el primero silenciosamente sin emitir `is-hide` en él. El evento se emite solo cuando el atributo cambia. Hay pérdida de observabilidad.
  - **`md-editor.ts` usa `document.execCommand`**: deprecated API; tests deben anclar la regresión si se elimina, y validar el comportamiento con `<dialog>` `light-dismiss` y `popover` API.
  - **`ui.ts` `html` template tag**: el escape usa `&#39;` que es correcto, pero `el()` no escapa `innerHTML` ni `html` attrs — surface XSS si una app lo usa para inyectar data no confiable.
  - **`window.ts` Tab focus-trap**: solo opera si el foco está *dentro* de la ventana — un screen reader que sale con `Esc` o click-outside queda fuera; no hay aviso `aria-hidden` al body para evitar lectura de fondo.
  - **`command-palette.ts` `aria-activedescendant`**: no se setea, aunque los resultados son `role="listbox"` con opciones. Lectores de pantalla no saben cuál está activo cuando se navega con flechas.
  - **`audit-components.ts`**: walk excluye `_shared` y `node_modules`-like, pero el regex `\.js$` ignora los `.ts` que existen (p.ej. los wrappers históricos como `intersection-observer.ts`). Falso negativo masivo.
  - **`heatmap.css`** define `--is-heatmap-text` local que pisa `var(--is-text)`; sin `prefers-reduced-motion` la `transition: opacity 120ms` se ejecuta siempre — accesibilidad.
  - **`web-share.ts`**: si `navigator.canShare` devuelve `false` para los `files`, los borra y comparte sólo texto. No hay forma de pedir feedback al usuario de que se degradó la compartición.

## Gaps transversales recurrentes

1. **Listeners globales sin teardown simétrico** — `wake-lock.ts` (`visibilitychange`), `observer.ts` (re-conexión en `slotchange` que reemplaza el observer sin desconectar el anterior para `mutation`), `floating.ts` (`scroll/resize` y ResizeObserver — sí desconecta, pero `#setup` se llama desde `attributeChangedCallback` sin `disconnect()` previo del RO viejo). Patrón a documentar y refactorizar: helper `withTeardown(observerFactory)` que asegure disconnect antes de re-setup.

2. **`setInterval` que sobrevive al quitar el atributo** — `relative-time.ts` y `format.ts` limpian el interval en `disconnectedCallback` y al cambiar `sync`, pero NO verifican si `#timer` es null antes de re-crearlo. Si el atributo se quita y se vuelve a poner rápido, hay ventana de doble interval.

3. **`command-palette.ts` y otros overlays no usan `aria-activedescendant`** — la navegación con flechas cambia `#active` pero los lectores de pantalla no saben qué opción está activa (sólo se aplica la clase `is-active`). Necesita `resultsEl.setAttribute('aria-activedescendant', option.id)` y que cada `<li role="option">` tenga `id` único.

4. **Falta de `prefers-reduced-motion` en animaciones CSS** — `heatmap.css` (`.cell { transition: opacity 120ms }`), `command-palette.ts` (transición de show/hide del dialog), `window.ts` (transiciones de maximize/minimize via CSS). Patrón transversal: cualquier `transition` > 100ms debería tener su contraparte `prefers-reduced-motion: reduce`.

5. **XSS surface via `el({html: …})` y `html\`<div>${raw(x)}</div>\``** — `ui.ts` confía en que el consumidor use `raw()` con cuidado. No hay opción para deshabilitar `raw()` globalmente o un linter. Tests deben anclar que `escapeHtml` se aplica por defecto en strings.

6. **`<dialog>` `light-dismiss` + `popover` API coexistencia en `md-editor`** — usa `popover` API para top-layer en fullscreen pero `<is-dialog light-dismiss backdrop-variant="basic">` ya provee su propia lógica. Tests deben verificar que las dos no se contradicen (Escape cierra via `cancel` del dialog, no via popover).

7. **`document.execCommand` en `md-editor.ts` y `md-render.ts`** — deprecated pero central al bold/italic. Tests deben documentar el comportamiento esperado y dejar snapshot para detectar regresión si se reemplaza por `InputEvent` + range API.

8. **Falta de `aria-live="polite"` en footer meta del `md-editor`** — `#ftMeta` (chars, bytes, updatedAt) se actualiza en cada input pero sin `aria-live` (sí está — línea 96: `aria-live="polite"`); otros elementos dinámicos como el `#vars-list` no tienen live region.

9. **Single-popover enforcement con observabilidad rota** — `popover.ts` `openPopover` global cierra el primero al abrir el segundo SIN emitir `is-hide`/`is-after-hide`. Consumidores que esperan estos eventos no se enteran. Documentar como bug.

10. **Audit script ignora `.ts`** — `audit-components.ts` línea 19 regex `\.js$` deja fuera todos los wrappers `.ts` (`intersection-observer.ts`, `mutation-observer.ts`, `resize-observer.ts`). Falso negativo masivo.

## Discrepancias de nomenclatura

- **`<is-format-bytes>` vs `<is-format type="bytes">`** — ambos hacen lo mismo; format.ts es el "todo-en-uno" pero format-bytes.ts es standalone y más rápido. Documentado en comentarios, no es bug.
- **`is-intersection-observer`/`is-mutation-observer`/`is-resize-observer`** vs `<is-observer type="…">` — los tres son alias (líneas 21, 19, 17 de cada .ts). El audit script NO los detecta (gap por regex `.js$`).
- **`is-popup` ya no existe** — comentario en popover.ts línea 15 lo confirma; `is-popover` es el único.
- **`script type="text/markdown"` vs `script type="application/json"`** — md-editor/md-render aceptan `text/markdown|md|plain`; command-palette acepta `application/json` (regex `/json/i`). Ambos intencionales.
- **`data-popover="close"` en `popover.ts`** vs **`createPopupDismiss`** (popup-dismiss.ts) — popover.ts implementa su propio dismiss (líneas 241-250) en vez de usar el helper compartido. Documentado en popup-dismiss.ts como comentario "ese anclaje es distinto a propósito"; sin embargo el caso de popover (anchor click toggle + outside click) calza con `onOutside`/`onKeydown` del helper. **GAP sugerido**: refactor popover.ts para usar `createPopupDismiss`.

## Notas para el runner de tests

- **Stack de testing**: el proyecto actual NO tiene runner de tests unitarios para componentes (sólo `src/utils/health/*` y `pnpm test:e2e` con Stagehand). Para implementar las propuestas se sugiere:
  - **Unit tests**: `node --test` (built-in, ya usado en `package.json` test script) + `@web/test-runner` o `@open-wc/testing` para DOM mocking de custom elements (happy-dom / jsdom).
  - **E2E**: Playwright (ya instalado en `devDependencies`) + `@browserbasehq/stagehand` para AI-driven assertions.
- **Helpers de mocking necesarios**:
  - `IntersectionObserver`/`ResizeObserver`/`MutationObserver`: globals en jsdom no implementados; polyfill `@juggle/resize-observer` o mock manual.
  - `navigator.wakeLock` / `navigator.share` / `navigator.canShare` / `navigator.clipboard`: `Object.defineProperty(navigator, 'wakeLock', { configurable: true, value: {…} })`.
  - `customElements.get`: para verificar registro idempotente.
  - `requestAnimationFrame`/`cancelAnimationFrame`: jest fake timers o `vi.useFakeTimers()`.
- **Selectores comunes para tests**:
  - Shadow DOM: `element.shadowRoot.querySelector('.x')` (todos usan open shadow).
  - `exportparts`: `getComputedStyle(lightQuerySelector('is-popover::part(popup)'))`.
- **Patrones de setup**:
  - `appendChild` al `<body>` para que `connectedCallback` se dispare; `removeChild` antes de cada test para limpiar listeners.
  - Para `<is-floating>` y `<is-popover>`: anchor externo (`<button id="t">`) fuera del shadow.
  - Para `<is-md-editor>`: `value` mínimo + `open` para abrir el diálogo.
- **Timeouts**: animaciones y transitions usan `120ms`/`300ms`; timeouts de test >= 500ms.
- **Cleanup**: `document.body.innerHTML = ''` entre tests evita fuga de popover/window global state.
- **Cobertura mínima**: ≥80% branch coverage por testable (excluyendo ramas `/* noop */` y fallbacks catch documentados como "expected").
