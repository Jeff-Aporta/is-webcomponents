- **Lenguaje(s)**: TypeScript (.ts) + JavaScript (.mjs) + HTML.
- **Tests existentes**: ninguno para los 16 scripts y 2 pages. Para los 2 HTML demos de ER existen tests `.test.mjs` en `demos/diagramas/ER/_testing/` (`er-static.test.mjs`, `er-static-server.test.mjs`, `er-editor.test.mjs`, `er-edge-cases.test.mjs`, `er-stagehand.test.mjs`, `er-attributes.test.mjs`) — pero NO son tests para los HTML en sí, sino para `<is-er-diagram>` consumiendo la página.
  - Categorías cubiertas en ER: snapshot, round-trip, edge cases, a11y teclado (Ctrl+Z, Escape), undo multi-paso, atributos, panel attrs.
  - Las páginas `ecosystem.ts` y `home.ts` no tienen tests; los HTML `er-static.html`/`index.html` tampoco tienen tests específicos de su markup/contenido.
- **Riesgos identificados** (pre-auditoría rápida):
  - 13 scripts hacen fetch HTTPS (iconify, github pages, jsdelivr, api.iconify.design): ninguno tiene timeout, abort signal, retry, ni backoff. Un socket colgado deja el proceso colgado indefinidamente.
  - `diag-failures.mjs` ignora el stderr de Node cuando es un fallo de `node:test` por timeout (no filtra `timeout`/`uncaughtException`/`ERR_TEST_FAILURE`).
  - `download-icons.ts` mantiene 32 conexiones simultáneas sin circuit breaker; un 5xx en cascada sobre 13K-300K SVGs nunca termina.
  - `fix-private-fields.ts` parsea JS con regex sobre `class X extends HTMLElement { … }` con 1 nivel de anidación — falla con clases anidadas, mixins declarados como clase, o bloques con comentarios que contienen `}`.
  - `fix-icon-viewbox.ts` confía en `api.iconify.design/<prefix>.json?icons=…` y no trata rate-limit (429) como caso distinguible de 200 con cuerpo inválido.
  - `migrate-previews-to-json.ts` borra HTML al final sin rollback; un crash a mitad borra la fuente sin haber escrito el .json.
  - `ts-campos-dom.ts` y `ts-inferir-params.ts` usan el parser de TS y verifican `parseDiagnostics` — pero no verifican que la edición no introduzca errores semánticos (`tsc --noEmit` debería ser la verificación).
  - `ts-revertir-inferencia.ts` lee stderr/stdout de tsc con un regex que requiere `error TS2339|2571|18046`. TS 5.x añadió nuevos códigos para "Property X does not exist on Y"; un update del compilador rompe el script silenciosamente.
  - `update-spec-paths.mjs` reemplaza paths en TODOS los `.md` y `.ts` de specs y guardianes — un nombre de archivo de test que casualmente coincida con un nombre de icono (p.ej. `dist.test.ts`) se reescribe sin querer.
  - `pages/ecosystem.ts` mete HTML con `innerHTML` construido por concatenación: `${esc(m.id)}` etc. La función `esc` escapa `& < > "` pero no atributos; un `m.path` con backtick/quote rompería el `innerHTML`.
  - `pages/home.ts` añade un `<button>` con `appendChild` por cada `CON_DEMO` encontrado — duplica botones si `mount()` se llama dos veces (chrome reusa el `is-main` entre previews). El `unmount()` es no-op, así que los listeners del primer mount persisten hasta el siguiente.
  - `er-static.html` confía en `customElements.whenDefined('is-er-diagram')` y aplica `visibility: hidden` hasta entonces. Si el bundle no resuelve el custom element (404), el host queda invisible sin feedback.
  - `index.html` (catálogo de demos) no tiene `lang`/i18n, no tiene meta OG, y los `<a class="card">` no exponen `aria-label`/`aria-describedby` apuntando a la descripción.

- **Tipo de proyecto**: library (webcomponents) + CLI toolchain interno + 2 páginas de preview + 2 demos HTML.

### `diag-failures.mjs` (scripts/diag-failures.mjs — 25 LOC)

**Tests existentes** (resumen): NINGUNO.

**Propuestas nuevas** (10):

1. **Exit code 0 cuando hay tests que fallan pero el script termina "OK"** — [edge-case]
   - **Setup**: crear `tests/dummy-fail.test.ts` que hace `assert.strictEqual(1, 2)`; ejecutar `node scripts/diag-failures.mjs`.
   - **Acción**: capturar `process.exitCode` al terminar y `console.log`/`console.error` acumulados.
   - **Assertion**: el script imprime las líneas coincidentes con `/FAIL|failing|faltan|esperaba|expected|AssertionError/` pero NO llama `process.exitCode = 1`. CI pasa el paso en verde aunque haya fallos.
   - **Coverage**: contract de exit-code para CI.

2. **Filtro regex pierde líneas que NO están en las primeras 50** — [edge-case]
   - **Setup**: un test que falla con el mensaje "expected" en la línea 80 de la salida.
   - **Acción**: ejecutar el script y leer stdout.
   - **Assertion**: la línea 80 no aparece en el output; `Math.min(lines.length, 50)` trunca el resto.
   - **Coverage**: pérdida de evidencia de fallos tardíos.

3. **No captura stderr-only de node:test (timeout, uncaughtException)** — [edge-case]
   - **Setup**: test que dispara `setTimeout(() => {}, 60000)` con `timeout: 100`; o `Promise.reject(new Error('boom'))` sin `await`.
   - **Acción**: ejecutar el script.
   - **Assertion**: `spawnSync` con `timeout: 30000` mata el hijo a 30s pero el script espera 30s por cada test; 3 tests × 30s = 90s totales. No hay forma de abortar antes.
   - **Coverage**: comando de timeout y captura de exit-codes no-cero.

4. **Rutas de test hardcodeadas — falla silenciosa si los tests se mueven** — [edge-case]
   - **Setup**: renombrar `src/utils/health/meta/nav-home-item.test.ts` a otro path.
   - **Acción**: ejecutar `diag-failures.mjs`.
   - **Assertion**: el script solo prueba los 3 paths del array. Si alguno no existe, `spawnSync` retorna exit 1 y stdout vacío — el script no avisa "no encontrado", solo imprime `=== src/utils/health/meta/nav-home-item.test.ts ===` sin contenido.
   - **Coverage**: paths faltantes vs. tests sin fallos.

5. **Regex demasiado laxa: incluye "ok" en matches falsos** — [edge-case]
   - **Setup**: test que imprime `console.log('fallo: status OK')` — sin fallar.
   - **Acción**: ejecutar.
   - **Assertion**: la regex `/FAIL|failing|faltan|esperaba|expected|AssertionError|expected:|actual:|ENOENT|fallo/i` casa con la palabra "fallo" (false positive) y la línea se imprime como si fuera relevante.
   - **Coverage**: precision del filtro.

6. **No distingue "no hay fallos" de "no se pudo correr el test"** — [edge-case]
   - **Setup**: tests que no existen (ENOENT).
   - **Acción**: ejecutar y leer stdout.
   - **Assertion**: ambos casos imprimen `=== <path> ===` y nada más. No hay forma de saber si fue "no falló" o "no se ejecutó".
   - **Coverage**: reportar el status del spawn (status code, signal, error) por test.

7. **El `cwd: root` resuelve mal si se invoca desde un subdirectorio** — [edge-case]
   - **Setup**: `cd src/components/forms && node ../../scripts/diag-failures.mjs`.
   - **Acción**: ejecutar y leer las primeras líneas de stdout.
   - **Assertion**: `process.cwd()` devuelve el subdirectorio; `join(cwd, 'src/utils/health/...')` apunta a una ruta inexistente. Los tests no se ejecutan y stdout está vacío sin error.
   - **Coverage**: contract de invocación (debe correrse desde la raíz).

8. **No expone el nombre del test ni el archivo:linea del fallo** — [edge-case]
   - **Setup**: tests reales que fallen.
   - **Acción**: ejecutar.
   - **Assertion**: las líneas filtradas no incluyen la cabecera TAP-style `# Subtest: foo.test.ts > …`. Se necesita grepping extra para mapear línea → archivo.
   - **Coverage**: parseo estructurado de TAP.

9. **No maneja `ENOMEM` ni errores de `spawnSync`** — [edge-case]
   - **Setup**: matar el proceso con `ulimit -v 100000` antes de ejecutar.
   - **Acción**: ejecutar.
   - **Assertion**: `r.error` está definido (`Error: spawn ENOMEM`), pero el script no lo distingue de un test que termina con exit 0 sin output.
   - **Coverage**: manejo de errores del spawn.

10. **Lista de tests es estática; añadir un test nuevo no aparece** — [edge-case]
    - **Setup**: añadir un nuevo test `meta/foo.test.ts` que falle.
    - **Acción**: ejecutar.
    - **Assertion**: el script solo recorre los 3 paths literales del array. El nuevo test no se evalúa.
    - **Coverage**: contrato de mantenimiento (sincronización manual).

9. **`mergeStatuses` prioriza 'failed' sobre 'downloaded' silenciosamente** — [BR]

10. **La cascada `cdn → iconify` no respeta `AbortSignal` aunque `downloadSVGOnce` reciba `opts`** — [ER]

## Gaps transversales recurrentes

1. **Falta de `AbortSignal`/`timeout` en fetches HTTPS de 13 scripts CLI** (`download-iconify.{mjs,ts}`, `download-icons.ts`, `fix-icon-viewbox.ts`): un socket colgado deja el proceso colgado indefinidamente. Ningún script tiene retry/backoff para 429/5xx. Patrón W3C `fetch` + `AbortSignal.timeout()` ausente.

2. **Cero cobertura de `prefers-reduced-motion` en scripts y demos HTML**: `home.ts` lo respeta parcialmente (early return), `er-static.html` lo menciona pero no lo aplica, `index.html` no tiene media query. Falta en 18/20 testables.

3. **`innerHTML` con concatenación sin escape completo en `pages/ecosystem.ts`**: `esc()` no escapa backticks ni atributos; `lab.innerHTML = '<label>…${c}…'` confía en `c`. XSS si el manifest es malicioso o viene de terceros.

4. **Doble fuente `.ts` + `.mjs` con defaults distintos**: `download-iconify.ts` (`outputDir: 'dist/assets/icons'`) vs `download-iconify.mjs` (`outputDir: 'assets/icons'`). Drift silencioso que rompe builds.

5. **`parseDiagnostics` API inestable**: `ts-campos-dom.ts`, `ts-inferir-params.ts`, `ts-revertir-inferencia.ts`, `ts-tipo-por-selector.ts` confían en `(sf as any).parseDiagnostics`. TS 5.4+ mueve esto a `internal`; el cast deja de funcionar y ediciones inválidas se escriben.

6. **Idempotencia no garantizada en scripts migradores**: `migrate-previews-to-json.ts`, `migrate-tests.mjs`, `rewrite-test-imports.mjs`, `update-spec-paths.mjs` no todos garantizan que ejecutar 2 veces dé el mismo resultado. El `botonesDeDemo` de `home.ts` duplica botones.

7. **Cero validación de `prefers-color-scheme: light`** en los 2 HTML demos y la página home: hardcoded `theme-dark` (`<html class="theme-dark">`). WCAG 1.4.3 ignorado.

8. **Falta de a11y landmarks y labeling en demos HTML**: ningún `<main id>`, ningún `aria-label` en custom elements, ningún skip-nav, ningún `aria-describedby` en cards.

9. **Listeners sin `signal` en scripts que reusan DOM**: `pages/ecosystem.ts` `filter?.addEventListener('input', …, opts)` con `opts` que puede ser undefined; `home.ts` reusa el `is-main` entre previews sin cleanup simétrico.

10. **Mensajes de error sin shape estructurado**: 14 scripts hacen `throw new Error(string)` sin clase custom. Imposible distinguir 4xx, 5xx, rate-limit, parse errors. Tests deben pattern-matchear strings.

11. **`text-transform: uppercase` en `<span class="tag">`** (index.html) sin `aria-label` lowercase: screen readers pronuncian con énfasis de mayúsculas. WCAG 1.3.1.

12. **CSP ausente en HTML demos**: ningún `<meta http-equiv="Content-Security-Policy">`. Si el dev añade第三方 content, XSS trivial.
