- **Lenguaje(s)**: TypeScript / JavaScript / CSS (todos ECMAScript module webcomponents + Node scripts).
- **Tests existentes**: ninguno de los `*.test.ts` listados en la consigna existe en `src/components/_shared/`, `src/components/forms/`, `src/components/helpers/`, `src/components/isp/`, `src/components/diagrams/`, `src/components/actions/`, `src/components/charts/`, `src/components/navigation/`, `src/previews/_kit/`, `src/utils/system/`, ni en `scripts/`. Hay tests paralelos en `src/utils/health/exhaustive/**` pero son health/audit, no cobertura del producto.
  - Categorías cubiertas por tests existentes: ninguna (gaps totales).
- **Riesgos identificados** (pre-auditoría rápida):
  1. `cdn-ref.resolveRef()` cachea SHA en `sessionStorage` y solo reintenta si el fetch falla. No hay tests de carrera entre dos llamadas concurrentes ni del TTL de la cache.
  2. `code-highlight.tokenizeCode()` mantiene `state` entre líneas (multilínea para `/* */`, template literals, regiones `<script>`/`<style>`); ningún test verifica el round-trip al re-renderizar un documento grande.
  3. `diagram-arrow.pathPoints` acepta SOLO `M/L/H/V` (case insensitive) pero los puntos H/V no emiten eje Y/X respectivamente al cambiar de comando — bug latente de regresión.
  4. `diagram-edit.attachNodeDrag` usa `setPointerCapture` y `evt.button !== 0` para ignorar click derecho; el test de "click derecho NO inicia drag" es trivial de olvidar.
  5. `controller-from-config.matchSqlFilter` parsea `campo='valor'` con regex; SQL injection en el campo o valor (e.g. `' OR 1=1--`) no se evalúa porque el filtro se aplica en memoria sobre el mock — pero la regex podría capturar mal.
  6. `masks-tokens.apply()` ignora silenciosamente caracteres no alfanuméricos; no hay tests para input "vacío con literales" o "todos los slots requeridos cubiertos pero con espacios".
  7. `url-nav.patchUrlState` hace `replaceState` y trata de borrar `dropLoose`; hay que verificar que NO borre `s` ni las `URL_STATE_RESERVED`.
  8. `response-cache.canonico()` ordena claves recursivamente; un payload con `undefined` o funciones puede romper JSON.stringify.
  9. `selection.toggleRowSelection` con `mode='multiple'` y `opts.range` debe respetar el orden de `orderedIds`; tests de regresión del bug histórico (JSDoc vs cuerpo) son obligatorios.
  10. Diagram preview handlers (`diagram-lightbox.preview.ts`, etc.) registran listeners globales (`document.addEventListener`) pero `unmount()` está vacío → memory leak en navegación SPA.
- **Tipo de proyecto**: frontend (webcomponents vanilla + galería de demos con scripts Node).

## Gaps transversales recurrentes

1. **Memory leak en preview handlers (`diagram-lightbox.preview.ts`, `lightbox.preview.ts`, `org-chart.preview.ts`, `sequence-diagram.preview.ts`, `mega-menu.preview.ts`)** — todos los `unmount()` son `/* no-op */` y los listeners quedan vivos tras navegar entre previews. Solución horizontal: registrar con `AbortController` y `signal.abort()` en `unmount()`.

2. **Tests de regresión del bug histórico `selection.ts:26` JSDoc vs cuerpo (keyof vs valores del enum)** — documentado en el comentario del código. Necesario tanto el test positivo (`'none'` desactiva) como el negativo (`'NONE'` NO desactiva, comportamiento correcto es documentar el bug latente).

3. **A11y/focus management ausente en los `*.preview.ts`** — al registrar handlers con `addEventListener` sobre botones fuera del shadow DOM, no se valida `aria-*` ni focus restoration tras eventos. Documentar como gap horizontal.

4. **CSS `prefers-reduced-motion` no aplicado uniformemente** — `button.css` lo respeta (spinner), `button-group.css` también (slotted), pero `chart.css` solo en `.animate` y `treemap.css` no aplica a `.tm-node__rect` transition (0.12s). Gap horizontal.

5. **`XSS / escapeHtml` cobertura en `code-highlight.lineToHtml`** — el helper hace escape de `&<>"` pero NO de `'`. Si un atributo HTML se construye con apostrofes en lugar de comillas, hay vector de escape. Documentar.

6. **Bearer token en `md-editor-api.authHeaders`** — si `cfg.token` devuelve `null` o `''`, no se añade header; si devuelve un objeto (caso pathológico), `String(token)` produce `'[object Object]'` que se envía como Bearer. Validar `typeof token === 'string'`.

7. **`url-nav.writeUrlState` y `URL_STATE_RESERVED`** — la constante existe pero `writeUrlState` no valida internamente que las keys recibidas NO sean reservadas; el caller debe saberlo. Documentar como invariante.

8. **`response-cache.vivo()` con `fetchFresh` que devuelve `undefined`** — el código hace `canonico(undefined) === 'undefined'`, así que la cache key cambia y se trata como nuevo. Documentar.

9. **`<is-chart>` `.tooltip` position: absolute** — la regla existe en `chart.css` (y `.tm-tooltip` en `treemap.css`) pero ningún test verifica que un chart con tooltip abierto NO empuj el contenido del plot. Test de regresión obligatorio.

10. **`diagram-arrow.pathPoints` con `H` después de `V`** — el parser NO emite el eje Y/X del punto H/V siguiente correctamente cuando hay un mixto. Comprobar regresión: `pathPoints('M0,0 V10 H20')` debería producir `[{0,0},{0,10},{20,10}]` (no emite X=20 con Y=10 como punto independiente — sí lo hace según el código, pero conviene asentar el contrato).

11. **`ts-codemod.tiparCamposPrivados` con campos no asignados a querySelector** — quedan sin tipo (`any` implícito en TS estricto). El codemod no avisa al usuario; documentar.

12. **`ux-audit.ts` timeout hardcodeado (1500ms en `canReach`)** — puede fallar en CI lento. Hacer configurable.

13. **`render.ts` sin sanitización de `section.titleHtml`** — se inyecta con `innerHTML`. Riesgo XSS si el JSON de preview viene de fuente no confiable (mitigado si los JSON son del propio repo). Documentar.

14. **`controles.ts.aplicarValor` con `prop:`** — si el valor es un `Function` o `Symbol`, el `host[prop] = valor` asigna sin coerción y rompe el render. Validar tipos permitidos.

15. **`smoke-dropdown-open.mjs`** — el path traversal check existe (`!path.startsWith(root)`) pero `decodeURIComponent` corre ANTES de la validación; con `%2e%2e/` se podría sortear. Verificar que la comprobación aplica tras decode.

## Notas para el runner de tests

- **Stack**: Vitest (`.test.ts` con `describe/it/expect`). Los tests `.mjs` usan Playwright directo (`chromium.launch`).
- **DOM**: jsdom + `customElements` shim para componentes web. Setup típico: `import {JSDOM} from 'jsdom'; beforeEach(() => { document = new JSDOM().document; ... })`. Para componentes que ya están registrados como `customElements.define`, importar el módulo del componente en `beforeAll`.
- **Mocks**: `vi.fn()` / `vi.spyOn()` para `fetch`, `sessionStorage`, `localStorage`, `indexedDB`, `navigator.clipboard`, `console.warn`, `history.replaceState`, `MutationObserver`.
- **Para los previews** (`*.preview.ts`), los tests no pueden ejecutarse sin DOM real de la galería → usar Playwright headless apuntando a `scripts/serve.mjs`.
- **Para los CSS** (`button.css`, `chart.css`, etc.), Vitest + jsdom no aplica — usar Playwright para renderizar el componente y leer `getComputedStyle` desde `page.evaluate`. Esto ya está implementado en `ux-audit.ts`; reutilizar el patrón.
- **Smoke** (`smoke-dropdown-open.mjs`) ya es Playwright directo. Reusar el http server local.
- **Path del runner**: `npx vitest run src/components/_shared/cdn-ref.test.ts` etc. para tests unitarios; `node scripts/ux-audit.ts --only is-button` para integración.
