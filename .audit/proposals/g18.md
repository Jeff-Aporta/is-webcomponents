# Auditoría UI/UX — function/components/isp+feedback+data+_shared+charts+overlays+layout+styles+scripts+utils (g18)

## Contexto
- **Testables del grupo**: 70 items. Categorías críticas:
  - `feedback/*.ts` (12 webcomponents: badge, cdn-snippet, confirm-modal, palette-selector, popconfirm, prefs-clear, progress-bar/ring, skeleton, spinner, tag, theme-toggle, toast, toast-item, tooltip)
  - `data/datagrid-core/*` (10 funciones: column-groups/state, csv-export, grid-model, pipeline-{filter,group,sort}, selection, server-datasource, value-formatter, viewport)
  - `isp/*.preview.ts` (10) + `isp/_shared/tree-view/{flex-options,helpers,render-rows}.ts` + `isp/{form-json,controller-from-config}.ts`
  - `_shared` bases (date-field-element, diagram-element-base, dom-utils, form-control-mixin, picker-element)
  - `charts`, `overlays`, `layout`, `styles`, `scripts`, `utils/health/motor/cli`
- **Tests existentes**: 0 (GREENFIELD).
- **Riesgos identificados**:
  - **`toast-item` con countdown + pausa + resume** es uno de los componentes más sutiles (timers + mouseenter/leave + focusin/out + restartTimer). Ningún test = bugs en UX feedback.
  - **`pipeline-filtering` + `pipeline-sorting` + `server-datasource`** forman la tríada de filtrado/orden/paginación del datagrid. Edge cases de tipos (text/number/date/set) sin cobertura.
  - **`grid-model` + `viewport`** gestionan estado global de la grilla; bugs afectan a todas las columnas/filas.
  - **`form-json`** es el puente `is-form` → `is-*` controls. Set/get de radios, sliders, multi-select tienen muchas ramas.
  - **`controller-from-config`** define contratos ISP (mock + real HTTP); bugs rompen demo offline.
  - **`theme-toggle` + `palette-selector` + `prefs-clear`** son broadcasters globales que afectan a TODOS los componentes. Race conditions en eventos.

## Gaps transversales

1. **Toast/tooltip lifecycle sin integration test**: ambos abren/cierran con timers y animations — sin E2E test, regresiones en cleanup son invisibles.
2. **`form-json` y `controller-from-config` son puentes críticos** entre ISP y webcomponents. Sin tests, cualquier cambio en `is-radio-group`, `is-slider`, etc. rompe el form-data round-trip.
3. **Datagrid cores (grid-model + column-state + pipeline-*) son inmutables y puros** — ideales para unit tests, pero cero cobertura. Riesgo alto de drift entre tests E2E y unit.
