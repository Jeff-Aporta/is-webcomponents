# Auditoría UI/UX — function/components/forms+components+feedback+cdn (g16)

## Contexto
- **Testables del grupo**: 43 items distribuidos entre `forms/*.preview.ts` (15), CSS animations (8: badge/spinner/skeleton/etc), CSS parts (12), `src/cdn/*.ts` (4), forms helpers (`masks-tokens.ts`).
- **Tests existentes**: 0 (GREENFIELD).
- **Riesgos identificados**:
  - **CDN subsystem** (`sheet-cache`, `ensure-element`, `load-plan`, `collect-is-tags`) es la infraestructura que sirve la lib en producción (CDN estático). Ningún test = riesgo de rotura silenciosa al deploy.
  - **`sheet-cache`** parchea `ShadowRoot.prototype.prepend` globalmente — un leak aquí rompe TODA la app. Sin tests de idempotencia ni cleanup.
  - **`masks-tokens`** define tokens de máscara para inputs telefónicos/RFC; bugs afectan validación de identidad fiscal en formularios LATAM.
  - **Forms `.preview.ts`** son demos interactivas: bugs ahí son bugs de demo (no críticos) pero son la primera impresión de usuarios nuevos.
  - **Feedback CSS** (spinner, skeleton, progress-ring) define animaciones — sin tests de `prefers-reduced-motion`, rompen WCAG.

## Gaps transversales

1. **CDN subsystem sin E2E test**: `sheet-cache` + `ensure-element` + `load-plan` forman una cadena. Ninguno prueba el flujo integrado (load manifest → preload → ensure → sheet adopt).
2. **Sheet-cache monkey-patch global**: cualquier reinstalación puede romper DOM global. Falta `dispose()` simétrico.
3. **`masks-tokens` sin tests de i18n**: acentos en tokens `A` pueden no funcionar correctamente en Firefox vs Chrome (Unicode regex).
4. **Forms previews carecen de tests de reduced-motion**: animaciones de focus, dropdown open, etc. deben respetar preferencia.
5. **Falta SRI integrity en load-plan**: si el manifest viene de CDN, no hay validación de integridad.

## Discrepancias de nomenclatura

- `loader.ts` aparece en `src/cdn/` (verificado en listado); NO está en el listado del prompt g16. Verificar si debería auditarse.
- `masks-tokens.ts`: NO leí su contenido; mis propuestas se basan en convención de tokens estándar (`9`, `A`, `*`, `#`). **Necesita confirmación** sobre tokens soportados.
- 8 archivos CSS listados como `css-part` (animation) en realidad son CSS animations (`spinner.css`, `skeleton.css`, etc.). Mi audit los cubre en g16 pero son **estilos puros** — mejor estrategia es screenshot diff tests que unit tests.
- `progress-bar.css` y `progress-ring.css` son CSS animations pero el `progress-bar.ts` está en g18 — cross-group coupling: cualquier test de animation debe coordinarse.
