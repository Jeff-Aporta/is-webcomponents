# Auditoría UI/UX — function/components/diagrams+forms+media+scripts+data+navigation+data-viz+utils (g14)

## Contexto
- **Testables del grupo**: 77 items distribuidos entre diagram specs (22), CSS de forms (14), media webcomponents (11), scripts cli (12), data webcomponents (9), navigation CSS (6), data-viz (2), e2e runner (1).
- **Tests existentes**: 0 archivos `.test.ts` presentes (verificado). GREENFIELD.
- **Riesgos identificados**:
  - **Specs de diagramas** (component-spec, sequence-spec, class-spec, er-spec) son los generadores de SVG/JSON: bugs ahí rompen el render de docenas de previews. Ninguno testeado.
  - **CSV export + value-formatter** son el puente crítica data→download: edge cases de RFC 4180 (comillas, saltos de línea, separador configurable) y format de date/number/boolean son focos.
  - **Server-datasource** implementa un parser SQL case-sensitive con quoted-string — riesgo de inyección o regresión en regex de split.
  - **Media components** (image-editor, media-recorder, icon-explorer) usan Canvas + MediaRecorder + HTTP iconify: muy pocas áreas cubiertas.
  - **Scripts CLI** sin tests: cambios en inferencia de tipos (`ts-codemod.ts`, `ts-jsdoc-a-tipos.ts`) pueden migrar mal código.

## Gaps transversales

1. **CSV sin BOM**: usuarios ES/PT necesitan BOM UTF-8 para Excel. Falta `opts.bom` en `rowsToCsv`.
2. **Diagram specs sin integración a11y**: la mayoría no emite eventos accesibles ni soporta `prefers-reduced-motion` ni `prefers-color-scheme`. Sería razonable un mixin `accessible-diagram` compartido.
4. **Media components son zonas muertas en testing**: media-recorder e icon-explorer requieren mocking de `MediaRecorder`, `IntersectionObserver`, `Clipboard API`, `fetch`. Una capa de helpers de mock centralizada ahorraría duplicación.
5. **Server-datasource: latencia simulada sólo aplica en fake-server**, no en tests con servidor real.
6. **Diagram specs sin benchmark de performance continuo**: integrar en CI un test con 100+ nodos.

## Discrepancias de nomenclatura

- `icon-explorer.preview.ts`: confirmar que el `.preview` indica "preview/demoflow" (paridad con discovery). El `.ts` es el entry del preview; el `icon.ts` es el componente real.
- `scripts/serve.mjs` vs `scripts/serve.test.ts`: NO localizado. Si es un script de dev, no debería tener test. Marcar como **gap**.
- `ts-resolve-hook-impl.ts`: NO leí; confirmar si es loadable.
