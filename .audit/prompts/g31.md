## Reglas duras para el sub-agente

1. **NO escribir tests**. Solo proponer. El capitán decide qué se implementa.
2. **Verificar primero** qué tests existen (read de `*.test.ts`). Marcar
   "ya implementado" si lo propones y ya está cubierto.
3. **Ser específico**: cada propuesta debe tener localizador exacto, acción
   concreta, y assertion verificable. NO propuestas genéricas ("debería ser
   accesible").
4. **Adaptar al componente**: NO usar el mismo formato para todos. Los forms
   necesitan validación en tiempo real; los charts necesitan interacción con
   datos; los modales necesitan focus management. Adapta la categoría al
   componente, no al revés.
5. **Pensar en UI + UX + a11y + integration + seguridad**: 10 propuestas que
   cubran todas las categorías son MEJOR que 10 de UI puras.
6. **Reportar gaps reales**: si encuentras que `role=tablist` no se setea, o que
   `prefers-reduced-motion` no se respeta, o que un `aria-live` no se eleva a
   `assertive` cuando es error — DOCUMENTAR como gap.
7. **Tiempo**: si llevas >10min, entrega lo que tengas. Calidad > cantidad.
